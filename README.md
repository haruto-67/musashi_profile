# ドラマー個人ページ

あるドラマーの個人ページ。GitHub Pages で公開する前提の静的サイト。
このファイルは「なぜこの形になったか」を残すためのもの。新しく作業を始めるときはここから読む。

---

## 1. 何のためのページか

- 対象は個人のドラマー。複数バンドに正規メンバーとして在籍しつつ、サポートでも臨時参加している。
- 目的は **経歴を見せること**。集客用の公式サイトではない。
- **検索には引っかからなくていい**（むしろ引っかからない方がいい）。名刺やDMからURLを直接踏んでもらう想定。
  - `<meta name="robots" content="noindex, nofollow">` と `robots.txt` で除外している。
  - ただしこれは「見つかりにくくする」だけで、URLを知っている人は誰でも見られる。報酬額など出したくない情報を載せる場合はそこを理解した上で。

## 2. 載せるもの（確定した構成）

上から順に：

1. **ヘッダー** — 全幅の写真＋名前
2. **自己紹介** — 短い文章
3. **条件（強調）** — 活動地域 / 報酬の目安
4. **条件（補足）** — 日程について / 機材
5. **SNS・連絡先** — X / Instagram / YouTube / TikTok / Mail
6. **BANDS** — 在籍バンド一覧。それぞれ紹介文とSNSリンク、写真
7. **SUPPORT** — サポートで入ったバンドの一覧（年＋内容）
8. **SCHEDULE** — これから3ヶ月のライブカレンダー
9. **フッター** — ひとこと＋noindexの注記

順番は BANDS → SUPPORT → SCHEDULE で確定。

## 3. デザインの経緯

最初にA〜Fの6方向を試して、**Aのセットリスト／リソグラフ風**が採用に。そこからA1〜A4の刷り色違いを検討。

並行して、本人の写真（深夜の路上、街灯のアンバーとティールの夜空、奥にドラムセット）を渡されて、その色と空気に寄せた案（streetlight）を作成。

最終形は **その2つのハイブリッド**：

- **ヘッダーと配色は streetlight から** — 全幅の写真、右上の街灯グロー、下へ夜色に溶けるグラデーション
- **それ以外の構成はA系から** — 刷り物っぽいノイズ、大きなバンド名タイポ、正方形のバンド写真、2カラムのSUPPORT、罫線のあるカレンダー

配色は写真から直接拾っている：

| 用途 | 値 | 由来 |
|---|---|---|
| 下地 | `#0A1418` | 夜空のティール寄りの黒 |
| 文字 | `#E8E3D8` | Tシャツの白 |
| アクセント | `#F0A63C` | ナトリウム灯のアンバー |
| 光のハイライト | `#FFD08A` | 街灯のいちばん明るいところ |

### 却下した案（同じ道を戻らないように）

| 案 | 内容 | 結果 |
|---|---|---|
| B | ドラムマシンのステップシーケンサーUI | 情報は整理されるが硬い |
| C | ドラムセットの俯瞰図がヒーロー、明朝＋真鍮 | 落ち着きすぎ |
| D | 方眼のスケジュール帳、手書き風 | カレンダーは良かったが全体の温度が違う |
| E | チケット半券モチーフ | 凝りすぎ |
| F | ネオン写真主体（マゼンタ×シアン） | 写真の実物と色が合わなかった |
| A2 / A3 / A4 | Aの刷り色違い（黒×オレンジ / 3色刷り / ティール×アンバー） | A4の配色思想は最終形に引き継いだ |

### 途中で変えた仕様

- 写真セクションを作る → **やめた**。写真はヘッダー・ポートレート・バンドごと・帯として本文に仕込む形に。
- カレンダーを3ヶ月ぶん縦に並べる → **やめた**。長すぎたので1つにして月切り替えボタンに。
- フッターに連絡先 → **やめた**。上部に移動。フッターはひとことと注記だけ。

## 4. ファイル構成

```
.
├── index.html      本文。テキストの書き換えはほぼここだけで済む
├── style.css       全スタイル。色は先頭の :root にまとまっている
├── gigs.js         ライブ予定のデータ（ここを更新するのが日常運用）
├── calendar.js     gigs.js からカレンダーと一覧を組み立てる
├── robots.txt      検索エンジン除外
└── images/         写真を置く
```

### images/ に入れるファイル

| ファイル名 | 使われる場所 | 推奨 |
|---|---|---|
| `hero.jpg` | ヘッダー全幅 | 横長・高解像度。上部に余白があると街灯グローが効く |
| `portrait.jpg` | 自己紹介の右 | 縦3:4 |
| `band-cyan.jpg` ほか | バンドごと | 正方形 |
| `live-wide.jpg` | BANDSとSUPPORTの間の帯 | 横長（24:7でトリミングされる） |

ファイルが無い場合は下敷きの色で塗られるだけなので、揃うまで放置してよい。
バンド写真・ポートレート・帯写真は CSS 側で自動的にアンバー×ティールのデュオトーンになる。ヘッダーだけは元の色のまま出す。

参照先は `index.html` の `style="--src:url('images/xxx.jpg')"` で指定している。

## 5. ライブ予定の更新

`gigs.js` の `GIGS` 配列に1行足すだけ。カレンダーは **今月から3ヶ月ぶん** を自動で表示するので、過ぎた月は勝手に消える。

```js
{d:"2026-09-05",     // 日付 YYYY-MM-DD
 b:"シアンの季節",     // バンド名（一覧に出る）
 sh:"シアン",          // 短縮名（カレンダーのマスに出る。長いと切れる）
 e:"深夜の三角形 vol.4",// ライブ名
 c:"下北沢",           // 地名
 v:"ERA",             // 会場名
 o:"18:30",           // OPEN
 st:"20:10",          // 出番
 n:"3マン"}           // 備考バッジ。不要なら ""
```

- カレンダーのマスには `sh` と `e` が出る（スマホでは `sh` のみ）。
- 下の一覧には 日付・曜日 / `b` + `n` / `e` / `c` `v` / OPEN と出番が出る。
- 同じ日に複数入れると、そのマスに積まれる。

## 6. 公開手順（GitHub Pages）

1. リポジトリを作ってこの一式を push（プライベートリポジトリでも Pages は使えるが、公開されるページ自体は誰でも見られる）
2. Settings → Pages → Source を `main` ブランチのルートに
3. 数分で `https://<ユーザー名>.github.io/<リポジトリ名>/` で見られる

ビルド不要の素のHTML/CSS/JSなので、Jekyll の設定などは要らない。

## 7. 公開前にやること

- [ ] ダミーの内容を差し替える。**現状の名前・バンド名・実績・ライブ・メールアドレスはすべて架空**
  - 「相川 涼太 / RYOTA AIKAWA」「シアンの季節」「TAPE OFF」「群青ラジオ」「Mellow Kitchen」など
- [ ] 報酬の金額を実際の額にする。額を出さず「応相談」だけにする選択肢もある
- [ ] SNSリンクの `href="#"` を実URLに
- [ ] `images/` に写真を入れる
- [ ] `<title>` と連絡先メールアドレスを差し替える

## 8. 検討の余地があるところ

- ヘッダーが画面の高さいっぱい（`min-height:86vh`）。スクロールしないと何のページか分からないので、`62vh` 程度に下げる選択肢もある
- カレンダーは3ヶ月固定。増やすなら `calendar.js` の `m<3` を変える
- ライブが増えてきたら `gigs.js` が長くなる。JSONに切り出して fetch する形にもできるが、GitHub Pages なら現状のままで困らない
